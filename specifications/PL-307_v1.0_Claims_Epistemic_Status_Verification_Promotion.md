## Key Changes from v0.5 to v1.0 LOCKED
Based on the empirical failure modes exposed during the REQ-006 v1.0 run, the following rules are now codified:

1. **Atomicity Rule (§17):** A single claim MUST contain only one discrete, falsifiable assertion. Compound claims MUST be split into separate claim objects.
2. **Contradictory Evidence Retraction (§20.2):** If a mapped `contradictory_evidence` object is invalidated, the claim's `contradiction_status` MUST be reassessed by a human. If no other contradictions exist, it may transition to `none`.
3. **Formalized State Values (§4, §20):** `system_flagged_for_review` is now an explicit, allowed value in the `status` dimension, triggered *only* by automated cascades (evidence retraction, staleness), which then route the object to a human queue for `under_review`. `verification_level` is recomputed downward; it is not set to a value named `recomputed_downward`.
4. **Mandatory Source Assessment (§9):** Any source counted toward verification MUST include a `source_assessment` block (rating, factors, rationale) to prevent unauditable quality judgments from leaking into binary independence fields.
5. **Explicit Promotion Event (§11):** Promotion is a governance action that MUST be recorded as a distinct event, including the actor, timestamp, and the exact text of any solo-founder disclosure (not merely a boolean flag).

*(All other sections of PL-307 v0.5 remain intact and are hereby LOCKED.)*
